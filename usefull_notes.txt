[NOTE]
strace -> used to the syscalls made when executing the binary
# Basic usage:
strace command
strace ls /tmp

# Trace a running process:
strace -p PID

# Count syscalls (performance summary):
strace -c command
# Output like:
# % time  seconds  usecs/call  calls  errors  syscall
# ──────  ───────  ──────────  ─────  ──────  ───────
#  46.15    0.001         73     19          mmap
#  15.38    0.000         31      5          read
#  ...

# Filter to specific syscalls:
strace -e trace=open,read,write,close ls /tmp
strace -e trace=network,ipc curl https://example.com

# Show timestamps:
strace -t command        # Absolute time
strace -tt command       # With microseconds
strace -T command        # Time spent in each syscall

# Follow children (processes created by fork/exec):
strace -f command
strace -ff -o strace-output command  # Separate output per PID

# Show signal receipt:
strace -e signal=all command

# Filter by error:
strace -e trace=all -e fault=read:error=ENOMEM command  # Inject errors

# Practical examples:

# Debug a failing nginx:
sudo strace -p $(pgrep nginx | head -1) -e trace=file 2>&1 | head -20

# See what config files a program reads at startup:
strace -e openat,open -f ./myprogram 2>&1 | grep "O_RDONLY"

# Debug network connections:
strace -e trace=network -f ./myprogram 2>&1

# Find why a program is slow (time each syscall):
strace -T -e trace=all ./slowprogram 2>&1 | sort -t'<' -k2 -rn | head -20

[VIRTUAL_FILE_SYSTEM]
- A dentry (directory entry) maps a filename to inode
- A dcache (dentry cache) used to avoid repeated disk lookups
- time + command : counts the time spent taken by the command
- A file object repsents an open file (created when a file is opened, destroyed when closed), it tracks:
    The inode (what file is open)
    The current position (file offset)
    Access mode (O_RDONLY, O_WRONLY, etc.)
    A pointer to file operations (f_op)
- Page cache most important component in linux performance
- The page cache is the reason why linux systems seem to use all the RAM, all unused RAM becomes a page cache. 
[OPEN_VFS_STEPS]
1. Kernel receives openat() syscall

2. Path resolution starts at '/' (or CWD for relative paths):
   - Look up '/' in dentry cache → hit (root dentry always cached)
   - Check permissions on '/' (x bit for current user)
   
3. Resolve 'home':
   - Look up 'home' in dentry cache under '/'
   - If hit: use cached inode
   - If miss: call filesystem's lookup() → reads directory from disk
   - Check permissions (x bit to traverse)
   
4. Resolve 'alice':
   - Same as above under 'home' inode
   - Check permissions
   
5. Resolve 'document.txt':
   - Look up in 'alice' directory
   - Get inode 11111
   - Check permissions (r bit for O_RDONLY)
   
6. Create file object:
   - Allocate struct file
   - Set f_inode = inode 11111
   - Set f_pos = 0
   - Set f_op = inode->i_fop (file operations table)
   
7. Call filesystem's open() method (if any):
   - e.g., ext4_file_open()
   
8. Assign file descriptor number to file object

9. Return fd to user space
